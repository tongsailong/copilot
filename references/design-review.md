# 设计审美咨询（可选通道）

Copilot 不定义设计标准，也不做设计裁决。本文件只说明：当调用方需要一次独立审美或设计认知意见时，
如何用现有认知通道提交材料、消费结论并登记采纳。设计判据、素材要求与产物规范归调用方的设计技能
（例如 DesignWise）所有；Copilot 只管认知调用、记录与采纳追踪。

## 边界

- **不是审批节点**：不进 G1–G3，不改阶段，不改完成条件，不阻塞任何已授权工程动作。
- **不改变决策主体**：主代理仍独自决定采用 / 修改 / 拒绝；认知输出是证据输入。
- **不是默认步骤，也不由用户点名**：普通工程任务、局部细节调整、同批图同问题不触发。
  是否发起由调用方按价值自主判断（影响面大 × 有真实产物 × 自评仍有实质不确定，三者同时成立）；
  调用方记录"发起/跳过及理由"，**跳过是正常结果**。Copilot 不替调用方排期，不设每阶段固定 CONSULT。
- **不重复付费**：同一批截图/材料 + 同一问题已评审过，除非出现新的实质产物（新版本、新状态、
  改版后重渲），否则不重问。重问必须 `--force --trigger ... --reason ...`。

## 两种模式：认知咨询与视觉咨询

| 模式 | 用于 | 材料 | 硬边界 |
|---|---|---|---|
| **认知咨询（可无图）** | 艺术指导论证链、视觉母题、产品气质与差异化、方向取舍 | brief / 事实与约束 / 方向卡（文字） | 认知**没看画面**，输出必须声明"未看画面"，不得评价像素、构图实现或视觉完成度 |
| **视觉咨询（必须有图）** | 真实方向图、原型截图、真机截图上的视觉判断 | 当前版本真实图片 + 交接材料 | 没有真实像素就不发起视觉结论；不得用 OCR、文字描述、源码分析冒充 |

两种模式不能混：认知咨询不能因为提到"视觉"就假装看过图，视觉咨询也不能只给文字材料却要求评画面。
一次调用只问本次真正不确定的事；缺陷、值得保留与创造性选项可以合并问，不为同一批材料拆成多次调用。

## 材料：按模式准备

**视觉咨询**：`cognition-consult` / `cognition-plan` / `cognition-review` 支持 `--image <路径>`（可重复，最多 6 张，
单张 ≤ 8 MB，合计 ≤ 24 MB，PNG/JPEG/WebP）与 `--image-note`（与图片顺序一一对应）。
图片以 Responses API 的 `input_image` 内容块提交，与其他材料同轮进入模型上下文。

**认知咨询**：只提交文字材料（brief、已核实的产品事实与约束、方向卡），并在材料中写明"无图，
不要评价画面"。不要为了凑格式提交无关图片，也不要把无图咨询的结果当成视觉评审。

- 每张图必须是**当前版本的真实产物**（概念图渲染、原型截图、真机截图），文件存在、可解码。
- 状态与审计只记录 `name/mime/bytes/sha256/width/height/label`，**不写 base64、不写绝对路径**；
  请求阶段 base64 只存在于内存中的 `data_url`。
- `images_sha256` 会进入请求指纹，图片变化即视为新材料，不会被旧的纯文本结论复用。
- 禁止用 OCR 结果、文字描述、HTML 源码、代码分析代替图片，让认知"看到"它没看到的东西。
- 禁止把历史修复后的截图标注成修复前版本；版本不符就不提交，或如实标注为历史参照。

文字材料只需补齐图片给不出的信息：产品目标与用户场景、本版方向与视觉 DNA（一句话）、
页面与状态清单、设备与设计基准、每张图的来源版本与 sha256、相比上次评审的改动。
**不要**灌入完整项目文档、设计技能全文、构建日志或重复报告。

## 提问：默认九问 + 可选创造性问题

**九问是视觉咨询的通用兜底**；调用方已给具体问题时，以调用方问题为准，不要求两边逐字一致。
一次咨询围绕真实画面问，问"哪里、为什么、怎么改"，不问"好不好看"：

1. 这一版是否有独特且站得住的视觉概念，还是可以套到任何同类产品上？
2. 第一眼落点对不对？用户最该先看到的信息是不是视觉最重的元素？
3. 构图与视觉重量是否协调：主体、留白、边缘元素之间有没有互相争夺？
4. 色彩、字号层级、材质、光线是否统一在同一套关系里？
5. 有没有明显的模板感或 AI 味：无来由的渐变、阴影、大圆角卡片、玻璃拟态、装饰形状？
6. 是否匹配该产品的用户、使用场景与定位（而不是匹配某种流行风格）？
7. 哪些视觉细节值得保留，不要在后一轮打磨里改掉？
8. 如果只能改三处，改哪三处对整体提升最大？给到具体位置与目标状态。
9. 主代理可能忽略的视觉问题是什么（跨页一致性、密度节奏、极端内容、深色模式）？

**创造性问题（阶段 0/1 可选，最多 2–3 个）**：找缺陷之外，也可让认知提构想与取舍：

1. 在不改产品事实与约束的前提下，有没有第二个更贴合内容的视觉母题？它来自哪个产品事实或行为？
2. 现有哪个细节值得放大成签名，而不是继续加装饰？
3. 论证链（产品事实 → 情绪目标 → 视觉论点 → 母题/形式 → 具体决定）哪一步最弱？给替代走法与代价。
4. 如果只能保留一个视觉决定，保留哪个？为什么？

创造性建议是**候选**，不替代真实生图、不改变用户已确认的方向；采纳与否由调用方决定。

## 输出：可核实，不要空话

要求认知按下列结构回答，缺失就追问或降级采信：

- **值得保留**：具体元素与理由（不是"整体不错"）。
- **问题**：位置（图号 + 屏幕区域/元素）+ 现象 + 为什么伤害目标 + 可执行修法。
- **主观偏好 vs 客观缺陷**：明确标注哪些是风格取向，哪些是违反可用性/可读性/一致性的缺陷。
- **不确定性**：裁切、缩放、压缩导致的看不清，写"无法判断"，不猜。
- **无图认知咨询**：输出必须声明"未看画面"，只讨论论证链、母题与取舍；出现像素、构图实现或
  视觉完成度评价时，调用方按无效意见处理。
- 不接受"更高级/更精致/更现代"这类没有指向的评价，也不要求打分。

## 登记与采纳

1. 调用结果进入 `cognition_calls`（`mode=CONSULT|PLAN|REVIEW`），审计含图片指纹。
2. 主代理逐条处理：`cognition-accept --call-id <id> --decision accepted|modified|rejected --note ...`，
   写明采纳到哪个产物、修改了什么、为什么拒绝。**未登记的结论不算已消费。**
3. 采纳后改了什么，用真实前后截图对照；`--image` 提交新图重问时属于新材料。
4. 不新建审美状态机、不建第二套设计记忆：设计结论的权威住所仍是设计技能侧的产物
   （方向卡、评审记录、覆盖率清单），Copilot 只留调用与采纳台账。
5. 审美经验回流时分类：跨项目原则需 ≥2 个项目或测量/脚本证据；单个项目的色板、风格、材质、
   布局属**项目视觉 DNA**，**不自动成为其他项目的默认审美**；用户偏好、一次性判断与未验证意见
   不升级为通用规则。沿用现有 `knowledge-manager` / Memory 通道，不新建审美记忆系统。

## 与 DesignWise 的接口

DesignWise 侧产出一份**评审交接包**（材料清单 + 图 + sha256 + 页面/状态 + 改动说明），
Copilot 侧原样作为 materials 与 `--image` 输入，不需要 Copilot 读设计技能文档，也不需要
DesignWise 依赖 Copilot。两侧各自可独立运行：没有 Copilot 时 DesignWise 照常自评，
没有 DesignWise 时 Copilot 不进入任何设计流程。
