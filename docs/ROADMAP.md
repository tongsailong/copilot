# ROADMAP

状态以 `STATUS.md` 的现场证据为准；此处只记录阶段目标与边界。

| 阶段 | 目标 | 状态 |
|---|---|---|
| **Phase 0–3** | 基础能力与自动驱动：CPA 调用、状态机、合同/轮次、证据包、四门、legacy 回填、审计与配额 | 已完成 |
| **Phase 3.5** | 原生双 Agent 验证：ZCode 原生 Executor / Reviewer 真实运行、身份与元数据采集、模型路由确认 | 已完成（离线协议与真实原生 Agent 能力分别验证） |
| **Phase 3.6** | 正式 Native Bridge：执行/复核信封、绑定校验、`native_agent.py` 从运行记录生成信封、异常与幂等、兼容性 | 离线部分完成；**完整 C4 真实端到端待授权**（2026-11-08 的 4 次真实调用只做链路自检，不算 C4） |
| **Phase 4** | 自动执行、复核、重判、收口：Reviewer 自动派发、SOL 自动闭环、可信复核记录升级 | **部分落地**：SOL 自动重判/收口与 PARTIAL 自动推进已实现、离线全链路验证；Reviewer 自动派发与可信复核记录升级未开始 |
| **Phase 5** | Copilot Skill 产品化：安装、配置、诊断、跨宿主适配、可观测性 | 未开始 |
| **Phase 6** | 完整自主工程闭环：从目标到交付的端到端自主协作 | 未开始 |

## 阶段边界

- Phase 3.6 的真实 SOL 调用需要单独的一次性授权（模型、请求数、预算、重试配置）；该授权不覆盖
  Phase 4 的自动派发或正式 REVIEW。
- Phase 3.6 不实现 Reviewer 自动派发、SOL 自动收口，也不把普通复核升级为 G4。
- Phase 4 已落地部分见 `docs/DECISIONS.md` 第 18 条与 `STATUS.md`；未落地部分仍需单独授权与
  实现，不以“接口已存在”视为完成，也不把离线/ Fake Upstream 证据写成已真实验证。
- 任何阶段都不得降低高风险 G4 的 fail-closed 条件。
