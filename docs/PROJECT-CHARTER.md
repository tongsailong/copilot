# 项目章程：Copilot × ZCode 原生 Agent 协作系统

本文件固定协作职责，不随阶段推进变化；能力与进度见 `ROADMAP.md`、`STATUS.md`。
现行协作基线是 ChatGPT 自定义指令（唯一权威治理基线）与用户级 `AGENTS.md`；本仓库不保存
其副本、不维护版本映射，ChatGPT 规则变化时只做受影响的增量同步。

## 角色分工（v9.0.0）

| 角色 | 负责 | 边界 |
|---|---|---|
| **用户** | 业务目标、优先级、重大取舍与授权 | 不承担现场工程实施；角色意见或安排不替代用户授权 |
| **ChatGPT（用户侧）** | 需求理解、产品与业务判断、目标定义、产品层方案规划、任务交接、结果验收 | 不假装拥有本地执行能力；不包办工程技术步骤 |
| **ZCode 原生 Agent** | **唯一工程执行与技术决策主体**：现场调查、工程规划、方案选择、实施、调试、测试、验证、原生子 Agent 调度；对技术路线与执行结果负责 | 不改变业务目标与规则；不扩大授权；高风险动作须授权 |
| **Copilot** | 运行于 ZCode 内的轻量协作治理：任务承接、合同与完成条件、状态机、证据桥接、审计、PARTIAL 持续推进、G1–G3 收口、SOL 生命周期路由 | 不实施工程；不替代 ZCode 的技术决策；不设置无意义的审批门；除显式 `sol-consult` / `sol-plan` / `sol-review` 外不调用远程模型 |
| **SOL CONSULT** | 默认认知入口：任务起点、关键证据冲突、方案失败、范围或风险变化时的一次零工具认知判断（目标理解/本质/路线取舍/风险/调查方向/再咨询条件） | 只提供认知输入；不执行工程、不做技术决策、不自动二审、不修改工程状态；不构成收口门禁 |
| **SOL PLAN** | 调查后的一次零工具规划判断：方案比较、优先级、阶段目标与验收关注点 | 不规定具体代码操作；最终方案与执行计划由 ZCode 决定；不影响门禁 |
| **SOL REVIEW** | 用户明确要求时的一次零工具独立复核，findings 以 advisory 进入台账 | 只做 REVIEW；不自动派生；不是普通开发前置门禁 |
| ~~**G4 只读复核**~~ | **v8.0.0 正式退役**；历史记录只读保留用于审计 | 不再参与准入、派生或收口；不得把历史 BLOCKED 改写为 PASS |
| **DesignWise** | 运行于 ZCode 内的设计方法与设计质量规范 Skill | 不替用户或 ChatGPT 作业务取舍；Copilot 不重复建设其工作流 |

**SOL 在 v6.0.0 退役决策通道，v7.0.0 恢复一次性 REVIEW，v8.1.0 恢复建议性 CONSULT / PLAN，
v8.4.0 短暂并入 THINK，v9.0.0 按生命周期恢复 CONSULT / PLAN 并成为默认认知引擎
（THINK 只作读取别名）。**
不恢复 DECIDE，不把 SOL 设为强制决策节点或状态门禁，也不得用其他远程大模型替代其认知或
审查职责。SOL 只能一次性阅读主代理提交的材料；结论是认知输入，不是工程决策。v8.1.0 起
统一 `gpt-6.2-sol`（`reasoning.effort=high`，零工具、单轮）。v8.0.0 起 G4 原生只读复核
退役，用户明确要求的独立审查由 SOL REVIEW 提供；CONSULT / PLAN 按生命周期在每次有明确
问题与决策价值时调用，没有硬性次数或 Token 上限。
历史 v5.x 文档中的“SOL 决策通道”表述只作历史记录。

**Executor** 是 ZCode 工程执行体系内的执行分工（主代理或子代理），不是与上述角色并列的
顶层角色。历史文档中的“Reviewer”只指已退役的复核执行方，不是独立角色体系。普通多轮
Reviewer 与 G4 只读复核均已退役；独立审查由 SOL 单轮复核承担。Provider 与模型可
`model: inherit` 跟随主代理。执行信封绑定见 `references/agent-bridge.md`；复核细则与历史
G4 记录见 `references/review.md`。

**协作闭环**：ChatGPT 定义目标 → ZCode 原生 Agent 承接 → Copilot 生命周期给出 SOL 建议 →
起点 CONSULT（非简单任务）→ 调查 → PLAN（需要多步/多方案时）→ 实施与验证（新证据触发
动态 CONSULT）→ 阶段复盘 / 收口判断 → ZCode 自主采纳/调整/否决并完成验证 → Copilot 做
轻量治理与证据桥接（必要时）→ 结果回传 → 验收。简单任务不强制经过 Copilot、SOL 或正式
REVIEW；正式 REVIEW 只在用户明确要求时进行，且授权在同一任务合同内持续有效。

## 固定原则

1. 用户确定业务目标、优先级与关键取舍；ChatGPT 侧负责需求与产品层方案；ZCode 负责工程实现
   与技术决策。
2. 执行结果与复核结果必须绑定任务、合同、计划、工作项与执行摘要；证据先登记后引用。
3. 子代理与执行方必须是不同 Agent、不同 Child Session；复核方不继承执行方判断。SOL
   零工具复核与执行方天然隔离，但只提供建议。
4. G1–G3 保持 fail-closed：证据不足、绑定不符或台账未闭合时禁止收口；任何模型判断（含
   SOL）、流程台账或普通 PASS 都不能替代证据、测试与授权判断。G4 已退役，不再是活动门禁。
5. PARTIAL 不是终点：持续派生工作项并推进，直到 PASS 或真实 BLOCKED（缺授权/决策/资源/
   外部限制）。
6. 源码仓库是唯一真源；运行时目录只由 `scripts-sync/sync_runtime.py` 单向下发。
7. 真实外部调用、提交、推送、发布、部署均需明确授权；不设人为轮次 / Token / 费用阈值作为
   停止条件。SOL 单轮复核属于任务成本，失败不阻断主代理继续。
8. 历史审计、裁决、证据与 SHA-256 只增不改；退役材料明确标注为历史，不因清理名称而删除。
